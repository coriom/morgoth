# P1 comparison protocol

The primary metric is independently accepted task completion. Secondary measures are aggregate model calls, acknowledged actions, no-change actions, loops, high-level revisions, abstentions, fixed protocol failures, request elapsed time and available memory/residency evidence. A legal click, plausible subgoal or visible marker is not success.

The direct reference is the existing six-call benchmark on the same reviewed synthetic fixtures. Its controller, task inputs, dynamic action IDs, fresh-DOM policy, trace manifest and independent checker are retained. A fair future comparison uses the same fixture, objective, target, expected result, selected model, code revision, total six-call ceiling and comparable model residency; only mode changes. Operator attempts must be separately consented and sequential. P1's one-shot command runs hierarchy only and makes **no silent direct-mode comparison**. Existing direct-mode operator evidence is historical, not a paired randomized trial.

Scripted model responses exercise both modes against actual confined Chromium. Inventory, catalog, support and the changed-layout route each need four browser actions under the scripted correct sequence: direct action uses four model calls; hierarchy uses one subgoal call and four action calls. The earlier deferred two-input fixture needs five actions and exactly six hierarchical calls. It was introduced after an earlier generic controller freeze, but was available to the P1 engineer and is not a blind holdout. A less direct changed-layout route can require six actions, so hierarchy cannot complete *that route* under the unchanged six-call budget if it needs any high-level call. This is a structural budget limitation, not model inferiority. The offline lexical reference completed four earlier fixtures in four or six actions and abstained on deferred; it remains an offline reference, never a fallback. Scripted high-level abstention on an unsupported objective executed zero browser actions.

The scripted responses know the correct control sequence; their results prove transport, resource accounting, policy and rendered acceptance only. They do **not** establish that Ollama can generate a useful subgoal or choose the subsequent actions. A single future live success would establish one completed synthetic mission, not statistical superiority, general software mastery or production qualification. A future failure should be interpreted using the fixed categories in the acceptance document, preserved synthetic control trace and bounded timing/resource fields.

No new fixture was developed after P1 code was frozen. Existing relayout and deferred fixtures offer layout and value-binding variation but have same-team contamination. A later independently authored interface and repeated paired trials would be needed to measure transfer more credibly. If hierarchy spends the six calls on advice/replanning without acceptance, compare against direct action and consider removing this adapter rather than raising budgets by default.
